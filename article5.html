🚀 From Jira to Tests in Seconds: Automating Playwright Test Generation with GitHub Copilot & MCP

📅 April 1, 2026 • 5 min read

One of the biggest pain points in test automation has always been the gap between requirements and implementation. A Jira ticket describes what needs to be validated. A test file contains what was actually automated. In between, there's a translation step — manual, error-prone, and often inconsistent.

I recently built a workflow that closes this gap using GitHub Copilot in VS Code, the Atlassian MCP server, and the Playwright MCP server. The result: Playwright tests generated directly from Jira requirements — with no copy-pasting, no interpretation drift, and a dramatically faster feedback loop.

🔧 What I Built

1. Setting Up the Playwright MCP Server

The first step was connecting Copilot to a live browser context via the Playwright MCP server. This gives Copilot the ability to reason about web interactions — page navigation, form inputs, assertions — and translate them directly into executable Playwright test code.

2. Integrating the Atlassian MCP Server

Next, I wired up the Atlassian MCP server to bring Jira context directly into VS Code. With this integration, Copilot can read ticket details — including the description, acceptance criteria, and validation rules — without me ever leaving the editor. The ticket becomes the source of truth for what tests need to cover.

3. Creating the Jira Task

I created a Jira task for the invalid login / invalid credentials flow. The ticket included:

  • Clear requirements describing the expected behaviour
  • Acceptance criteria specifying what must hold true after a failed login attempt
  • Specific validations — error message displayed, user remains logged out

Writing a well-structured ticket turned out to be a key part of the workflow. The richer the acceptance criteria, the more precise the generated tests.

4. Prompting Copilot to Generate Tests

With both MCP servers active, I prompted Copilot to:

  • Read and parse the Jira ticket
  • Extract the validations from the acceptance criteria
  • Generate Playwright test cases covering each scenario

Copilot processed the ticket content and produced a structured test file — complete with page interactions, assertions, and descriptive test names that mapped directly back to the Jira acceptance criteria.

5. Executing and Verifying the Tests

The generated tests were executed against the application. Both validations passed:

  • ✅ Error message displayed for invalid credentials
  • ✅ User remains logged out after a failed attempt

No manual edits were needed. The tests ran correctly on the first pass.

✨ Outcomes

  • ⏱️ Faster test creation — going from a Jira ticket to a passing Playwright test took a fraction of the time it would manually.
  • ✅ More consistent validations — because the tests are derived directly from acceptance criteria, there's no risk of a human misreading or skipping a condition.
  • 🔗 Tighter requirements-to-coverage alignment — every acceptance criterion in the Jira ticket has a corresponding test assertion. Traceability becomes almost automatic.

🧠 Why This Matters

This isn't just a productivity trick. It represents a shift in how automation is created.

When AI can read requirements and write tests, the bottleneck moves from implementation to definition. Good requirements now directly produce good automation.

This also encourages QA engineers and developers to invest more in writing clear, structured acceptance criteria — because the quality of the output is directly tied to the quality of the input.

🔮 What's Next

This workflow is a foundation. A few areas I'm actively exploring:

  • Broader coverage: Applying the same approach to complex, multi-step flows beyond login
  • CI/CD integration: Triggering test generation automatically when a Jira task moves to a certain status
  • Test maintenance: Using Copilot to update existing tests when acceptance criteria change in Jira
  • API test generation: Extending beyond UI tests to generate Playwright API test cases from ticket specs

🔧 Key Technologies Used

  • GitHub Copilot (VS Code)
  • Model Context Protocol (MCP)
  • Playwright MCP Server
  • Atlassian MCP Server
  • Jira (Requirements & Acceptance Criteria)
  • Playwright (Test Automation Framework)
